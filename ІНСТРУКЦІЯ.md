# Двомовна презентація наживо — інструкція

**Одне посилання, один екран PIN-коду.** Роль визначається введеним кодом:
- **PIN учасника** → вибір мови (UA/EN) → перегляд слайдів, які гортаються синхронно з ведучим;
- **PIN ведучого** → пульт керування: гортання слайдів, лічильник учасників, QR-код, публікація слайдів.

## Файли

| Файл | Де лежить | Призначення |
|---|---|---|
| `index.html` | на хостингу | сам застосунок (без текстів слайдів) |
| `slides.js` | **лише у вас на ноутбуці** | тексти слайдів UA/EN; **не завантажуйте на хостинг** |
| `database.rules.json` | вставляється у Firebase | правила доступу |
| `publish-slides.mjs` | у папці проєкту | публікація `slides.js` з командного рядка |
| `convert.py` | у папці проєкту | конвертація PPT/PPTX/PDF у слайди |
| `decks/` | на хостингу | зашифровані картинки слайдів |

**Чому слайди окремо:** вони зберігаються в хмарі Firebase і видаються лише тим, хто ввів правильний PIN. На публічному сайті текстів немає, тож навіть перегляд коду сторінки без PIN нічого не покаже.

## 0. Перевірка в демо-режимі (без налаштувань)

1. Покладіть `index.html` і `slides.js` в одну папку й відкрийте `index.html` у Chrome або Edge.
2. Вкладка 1: введіть PIN учасника **246810** і оберіть мову.
3. Вкладка 2: відкрийте той самий файл і введіть PIN ведучого **135790**.
4. Гортайте слайди у вкладці ведучого — вкладка учасника перемикається слідом.

Вхід діє в межах вкладки, тому на одному комп'ютері можна одночасно відкрити і пульт, і вікно учасника. Кнопка **⏏** виходить і повертає до екрана PIN.

## 1. Створіть проєкт Firebase (≈10 хв, безкоштовно)

**Firebase** — хмарна платформа Google. Тут використовуються два її сервіси:
- **Realtime Database** — база даних, яка миттєво розсилає зміни всім підключеним пристроям;
- **Authentication** — перевірка PIN-кодів.

1. Перейдіть на https://console.firebase.google.com → **Add project** → назва, наприклад `panel-nuou`. Google Analytics можна вимкнути.
2. **Build → Realtime Database → Create database** → регіон **europe-west1 (Belgium)** → **Start in locked mode**.
3. **Build → Authentication → Get started → Sign-in method → Email/Password → Enable**.
4. **Authentication → Users → Add user** — створіть **два** службові облікові записи. Email тут лише технічне ім'я: справжня пошта не потрібна, лист нікуди не надсилається.

   | Email | Password |
   |---|---|
   | `participants@panel.local` | **PIN учасника**, напр. `583920` |
   | `presenter@panel.local` | **PIN ведучого**, напр. `70412958` |

   Обидва PIN мають містити щонайменше 6 символів і **відрізнятися**. PIN ведучого робіть довшим (8+ цифр) і нікому не повідомляйте.

## 2. Налаштуйте права доступу

1. **Realtime Database → вкладка Rules**.
2. Вставте вміст `database.rules.json` (у ньому вже прописано `presenter@panel.local`) → **Publish**.

3. **Початковий стан доступу.** Realtime Database → вкладка **Data** → «+» біля кореня → додайте вузол `access` з трьома полями:
   - `open` = `true`
   - `notBefore` = `0`
   - `participantPin` = PIN учасника з кроку 1.4 (у лапках, як текст)

   Без цього вузла учасники не зможуть увійти, а пульт не покаже поточний PIN.

Результат правил:
- без PIN — жодних даних;
- з PIN учасника — лише читання слайдів і номера поточного слайда;
- гортати й змінювати слайди може лише ведучий.

## 3. Підключіть застосунок до Firebase

1. **Project settings** (шестерня) → **Your apps** → `</>` (Web) → **Register app** → скопіюйте `firebaseConfig`.
2. В `index.html` (текстовим редактором: Notepad++, VS Code) замініть
   ```js
   const FIREBASE_CONFIG = null;
   ```
   на скопійований об'єкт:
   ```js
   const FIREBASE_CONFIG = { apiKey: "...", authDomain: "...", databaseURL: "...", projectId: "...", appId: "..." };
   ```
   Переконайтеся, що є поле `databaseURL`. Якщо його немає, скопіюйте адресу `https://...firebasedatabase.app` зі сторінки Realtime Database.
3. Якщо на кроці 1.4 ви обрали інші email, змініть їх у рядках `PARTICIPANT_EMAIL` / `PRESENTER_EMAIL` та в `database.rules.json`.

`apiKey` — не секрет: він лише вказує на проєкт. Захист забезпечують PIN-коди та правила доступу.

## 4. Опублікуйте сторінку

**GitHub Pages** (безкоштовний хостинг статичних сайтів від GitHub):
1. На https://github.com створіть репозиторій (Public).
2. **Add file → Upload files** → завантажте **лише `index.html`** → **Commit**.
3. **Settings → Pages → Branch: main → Save**. Адреса сайту: `https://<логін>.github.io/<репозиторій>/`.

## 5. Завантажте слайди в хмару

1. Відкрийте сайт і введіть **PIN ведучого**.
2. Під слайдом натисніть **«📂 Обрати slides.js»** і виберіть файл на ноутбуці.
3. Натисніть **«☁ Опублікувати слайди»**, і напис зміниться на «✓ Актуально».
4. Після кожної правки `slides.js` повторіть кроки 2–3. Учасники отримають зміни миттєво, навіть під час виступу.

**Альтернатива — командний рядок:** у папці проєкту виконайте `node publish-slides.mjs <PIN ведучого>`. Скрипт прочитає `slides.js` і запише слайди в базу, тож браузер для цього не потрібен.

## 6. Конвертація готових презентацій (PPT / PPTX / PDF)

Скрипт `convert.py` працює на вашому ПК і перетворює готові презентації на слайди для застосунку. Firebase отримує лише невеликий `slides.js`, тож його безкоштовні ліміти майже не витрачаються.

**Підготовка (один раз):**
```
pip install -r requirements.txt
```
Для PPT/PPTX у режимі картинок потрібен встановлений Microsoft PowerPoint. PDF обробляється без нього.

**Два режими:**

| Режим | Що виходить | Коли обирати |
|---|---|---|
| `images` (типово) | кожен слайд стає картинкою, дизайн, шрифти й схеми зберігаються 1:1 | готова оформлена презентація |
| `text` | заголовки й пункти потрапляють у `slides.js`, оформлення бере на себе застосунок | потрібно правити тексти, або оформлення не важливе |

**Приклади команд** (у папці проєкту):
```
# Картинки, дві мови, вивантажити на GitHub і одразу опублікувати
python convert.py --uk Доповідь_UA.pptx --en Report_EN.pptx --title-uk "Назва" --title-en "Title" --push --publish <PIN ведучого>

# Лише текст, щоб відредагувати його в slides.js перед публікацією
python convert.py --uk Доповідь_UA.pptx --en Report_EN.pdf --mode text

# Одна мова: обидві версії показуватимуть ті самі слайди
python convert.py --uk Доповідь.pdf --push --publish <PIN ведучого>
```

**Важливо:**
- UA- та EN-версії мають містити **однакову кількість слайдів**. Приховані слайди PowerPoint не враховуються.
- Формати можна змішувати: наприклад, UA у PPTX, а EN у PDF.
- **Як захищено картинки:** вони шифруються AES-256-GCM і лежать на GitHub Pages у папці `decks/`. Ключ розшифрування є лише в `slides.js` (не потрапляє на GitHub) і у Firebase, звідки його отримують тільки учасники з правильним PIN.
- **Кожна конвертація додає нову презентацію до бібліотеки** (див. нижче) зі своїм окремим ключем. Попередні презентації залишаються.
- Прибрати набір картинок: `python convert.py --remove <ID> --push`. ID — це назва папки в `decks/`. Видалити всі попередні набори одразу: `--prune`.
- `--no-show` разом із `--publish`: лише додати до бібліотеки, не перемикаючи поточний показ.
- Без `--push` картинки залишаються лише на ПК, і учасники їх не побачать. Вивантажити їх можна пізніше: `git add decks && git commit -m slides && git push`.
- Параметри якості: `--width 1920` (ширина в пікселях), `--quality 82` (стиснення WebP, 1–100).

## 7. Бібліотека презентацій

Усі опубліковані презентації зберігаються в бібліотеці. На пульті ведучого є рядок:

**📚 Презентація: [список] ▶ Показати 🗑**

- У списку для кожної презентації вказано назву, кількість слайдів, тип (картинки або текст) і дату. Позначка **●** означає ту, яку зараз бачать учасники.
- **▶ Показати** перемикає всіх учасників на вибрану презентацію з 1-го слайда. Якщо показ уже триває, потрібне друге натискання для підтвердження.
- **🗑** видаляє презентацію з бібліотеки. Ту, що показується зараз, видалити не можна.
- **Картинки на GitHub кнопка 🗑 не видаляє**, бо сторінка в браузері не має доступу до вашого GitHub. Після видалення з бібліотеки виконайте на ПК:
  ```
  python convert.py --sync <PIN ведучого> --push
  ```
  Команда порівняє папку `decks/` з бібліотекою й прибере з ПК та GitHub усі набори, яких у бібліотеці вже немає. Один конкретний набір можна видалити так: `python convert.py --remove <ID> --push`.
- **Додати до бібліотеки:** `python convert.py … --push --publish <PIN>`, або `node publish-slides.mjs <PIN>`, або на пульті «📂 Обрати slides.js» → «☁ Додати в бібліотеку й показати».

У Firebase бібліотека займає лише кілька кілобайтів на презентацію (назви та ключі), тому безкоштовних лімітів вистачить на сотні презентацій.

**Автооновлення сторінки.** GitHub Pages дозволяє браузерам до 10 хвилин тримати сторінку в кеші. Тому кожна публікація містить мінімальну потрібну версію застосунку (`APP_VERSION` в `index.html`). Якщо в учасника чи ведучого відкрита застаріла сторінка, вона сама перезавантажиться в обхід кешу.

## Під час заходу

1. Відкрийте сайт на телефоні або ноутбуці й введіть PIN ведучого.
2. **«QR-код для учасників» → «Друкувати»**: на аркуші є QR-код і поле «PIN: ____». Впишіть **PIN учасника** від руки й розкладіть аркуші по чотирьох зонах.
3. Поки ви не натиснули **«▶ Почати»**, учасники бачать екран очікування. Угорі пульта видно, скільки людей підключено кожною мовою.
4. Гортайте кнопками **Далі/Назад**, стрілками клавіатури або кліккером.
5. Учасник, який під'єднався пізніше, одразу потрапляє на поточний слайд і може переглянути вже показані.
6. Пульт можна відкрити на двох пристроях одночасно (телефон + ноутбук): обидва керують тим самим слайдом.

## Керування доступом (на пульті ведучого)

Під слайдом на пульті є рядок **«Учасники»**:

| Елемент | Що робить |
|---|---|
| **PIN учасника: 123456** | поточний PIN; кнопка 👁 ховає або показує його (зручно, коли екран бачать інші) |
| **🔄 Новий PIN** | генерує новий 6-значний PIN. Усі підключені учасники **миттєво** повертаються на екран PIN-коду з повідомленням «Доступ закрито або PIN змінено». Старий PIN більше не діє |
| **⛔ Закрити доступ** | вхід для учасників вимкнено: усі підключені відключаються, нові не зможуть увійти навіть із правильним PIN. Ведучий працює далі |
| **✅ Відкрити доступ** | знову дозволяє вхід з **поточним** PIN |

Щоб уникнути випадкового натискання, «Новий PIN» і «Закрити доступ» спрацьовують після **другого** натискання. Після першого кнопка показує «Точно? Усі учасники вийдуть».

Аркуш для друку з QR-кодом («QR-код для учасників» → «Друкувати») автоматично містить **поточний** PIN. Після зміни PIN-коду аркуші треба передрукувати.

**Як це працює технічно:** PIN учасника — це пароль службового запису `participants@panel.local`. Пульт змінює цей пароль і записує в базу час зміни (`access/notBefore`). Правила бази пускають учасника лише тоді, коли доступ відкритий (`access/open`) і його вхід відбувся **після** цього часу. Тому старі сесії відключаються одразу, а не через годину, як було б після простої зміни пароля.

**Сценарій для заходу:**
1. Перед заходом натисніть «🔄 Новий PIN» і роздрукуйте аркуші.
2. Після заходу натисніть «⛔ Закрити доступ».

### Зміна PIN ведучого

На пульті натисніть **«🔑 Мій PIN»** і заповніть форму: поточний PIN, новий PIN і новий PIN ще раз → **Зберегти**.

- Новий PIN має містити **8–12 цифр**. PIN учасника завжди 6-значний, тож коди не збіжуться, і система однозначно визначає роль.
- Однакові (`11111111`) і послідовні (`12345678`) цифри не приймаються.
- Поточний PIN потрібен для підтвердження особи: так ніхто не змінить ваш код із залишеного без нагляду пульта.
- Пульти, відкриті на інших пристроях, працюватимуть до закриття вкладки, а для нового входу знадобиться вже новий PIN.
- Скрипт `publish-slides.mjs` теж приймає новий PIN: `node publish-slides.mjs <новий PIN>`.

**Забули PIN ведучого?** Firebase → Authentication → Users → `presenter@panel.local` → ⋮ → **Reset password** не підійде, бо лист піде на неіснуючу адресу. Натомість видаліть цей запис і створіть заново з тим самим email і новим паролем.

## Як повністю закрити платформу після заходу

| Рівень | Дія | Наслідок |
|---|---|---|
| Тимчасово | «⛔ Закрити доступ» на пульті | учасники не бачать нічого; можна знову відкрити |
| Прибрати слайди | Firebase → Realtime Database → Data → вузол `rooms` → 🗑 | у базі не залишиться жодних текстів |
| Вимкнути сайт | GitHub → репозиторій → Settings → Pages → **Unpublish site** (або зробити репозиторій Private) | посилання перестане відкриватися |
| Повністю | Firebase → ⚙ Project settings → внизу **Delete project** | проєкт, база і PIN-коди видаляються остаточно (Google тримає проєкт 30 днів на випадок відновлення) |

## Безпека — що варто знати

- PIN учасника захищає від сторонніх, але кожен, кому його повідомили, може переслати його далі. Матеріали з обмеженим доступом на слайди не розміщуйте.
- Дані зберігаються на серверах Google (регіон EU).
- Безкоштовний тариф Firebase (Spark) дозволяє до 100 одночасних підключень.
